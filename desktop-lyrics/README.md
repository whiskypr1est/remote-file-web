# 桌面歌词（悬浮窗客户端）

把虚拟桌面里**音乐播放器**的歌词，以一行大字浮在屏幕最上层 —— 关掉浏览器
之后也还在。仿网易云音乐的桌面歌词：白色字 + 黑色描边，暂停时半透明。

它**不在**虚拟桌面那个网页里，而是一个独立的小程序（Electron），装在每台
需要看歌词的机器上。之所以要独立：网页只能在浏览器窗口里画东西，而桌面歌词
必须浮在**所有**窗口之上、并且能在浏览器关掉后继续存在。

```
浏览器（音乐播放器）
      │  每 0.5 秒上报「现在在放什么」              POST /now-playing
      ▼
虚拟桌面服务端（局域网上那一台）
      │  广播给所有订阅者                          WS /ws/lyrics
      ▼
本程序（每台机器一个） —— 透明、无边框、置顶、鼠标穿透的一行字
```

## 一、快速开始

前置：**Node.js 18 或更高**（`node -v` 能看到版本号就行）。

```bat
cd desktop-lyrics
npm install          :: 第一次会下载 Electron（约 100MB）
npm start            :: 直接运行（开发用）
```

第一次运行会自动弹出「连接设置」窗口，填上**虚拟桌面服务端的地址**即可，
例如 `http://192.168.1.10:8000`（就是平时打开虚拟桌面的那个地址）。
不写 `http://` 也能认。

然后去虚拟桌面里打开音乐播放器放一首有歌词（同名 `.lrc`）的歌，歌词就会出来。

### 打包成安装程序

```bat
npm run dist              :: 同时生成「安装版」和「便携版」，产物在 dist\
npm run dist:portable     :: 只要便携版（免安装，双击就能跑）
```

产物：

| 文件 | 用途 |
| --- | --- |
| `desktop-lyrics\dist\桌面歌词-安装版-1.0.0.exe` | NSIS 安装程序，**按用户安装**（不需要管理员），带开始菜单/桌面快捷方式 |
| `desktop-lyrics\dist\桌面歌词-便携版-1.0.0.exe` | 单个 exe，双击即用，适合放 U 盘/网络盘 |

装完一台之后，把安装程序拷到其它机器直接装即可（**不需要**在每台机器上装 Node）。

### 如果 `npm install` 或 `npm run dist` 卡住/报错（国内网络）

**① Electron 的二进制**默认从 GitHub 下载，国内经常连不上（现象是 `npm install`
看起来成功，但 `npm start` 报 “Electron failed to install correctly”）。
**② 打包时的 NSIS/签名工具**也从 GitHub 下载，连不上时 `npm run dist` 会卡住。
两个都换成国内镜像即可（打包与安装各设一次，只对当前窗口有效）：

```bat
set ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/
set ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/
npm install
npm run dist
```

> **③ 如果 `npm run dist` 报 `ENOENT: ... rename 'dist\win-unpacked\electron.exe'`**
> 说明解压 Electron 压缩包时**漏文件**了（`electron.exe` 没写进去，`win-unpacked`
> 里只有几十个 dll/pak）。这是解压工具在某些机器上被打断/拦截导致的，跟项目无关。
> 本项目的 `package.json` 里为此设了：
>
> ```json
> "electronDist": "node_modules/electron/dist"
> ```
>
> 它让 electron-builder **直接从 `node_modules/electron/dist` 拷贝**，而不是自己
> 再解压一遍 —— 那个目录是 `npm install` 装 electron 时解压好的，内容最全。
> 所以正常情况下不用管它；万一日后 `npm install` 自己就漏文件了，
> 用 `python -c "import zipfile;zipfile.ZipFile(r'%LOCALAPPDATA%\electron\Cache\<哈希>\electron-v32.3.3-win32-x64.zip').extractall(r'node_modules\electron\dist')"`
> 手工补一次即可（压缩包在 `%LOCALAPPDATA%\electron\Cache\` 下）。

## 二、托盘菜单（唯一的操作入口）

悬浮窗本身**故意不接受鼠标操作**（否则玩游戏时一点它就切出去），所有设置都在
右下角托盘的图标上（右键）：

| 菜单项 | 说明 |
| --- | --- |
| **显示歌词** | 临时隐藏/显示。隐藏后仍在后台连接，勾回来立刻恢复 |
| **鼠标穿透（推荐开启）** | 默认开启。开启时鼠标点到的还是下面的游戏/软件，歌词只是一层字。<br>**要拖动歌词位置时先把它关掉**（关掉后窗口会一直显示，不会因为没放歌而藏起来） |
| **锁定位置** | 拖动定位完成后勾上，防止玩游戏时误拖 |
| **字号** | 小 28 / 中 40 / 大 52 / 特大 68 像素 |
| **显示进度条** | 底部一条细进度条（默认关闭，保持「一行大字」的干净观感） |
| **订阅用户** | 谁在放就显示谁（默认），或只订阅某一个用户名 —— 见下面第五节 |
| **连接设置…** | 服务器地址 / 订阅用户 / token / 外观 |
| **开机自启** | 开机后只在托盘待着，有歌在放时才浮出歌词 |
| **打开说明文档** | 打开本文件 |
| **退出** | 真的退出（关窗口不会退出，它是托盘常驻的） |

左键单击托盘图标 = 打开「连接设置」。

## 三、两点要先知道的事

1. **独占全屏的游戏盖不住这层字。**
   这是 Windows 合成器的限制，不是本程序的毛病 —— Discord、Steam、NVIDIA
   的浮层同样盖不住独占全屏。**把游戏改成「无边框窗口化」就正常了**，
   而且无边框窗口化的画面和独占全屏几乎没区别（现在多数玩家都这么设）。

2. **歌词的来源是音乐播放器的上报。**
   关掉浏览器不影响（歌词会一直显示，直到播放器停止/关闭窗口）；但反过来，
   如果播放器窗口关了、或者停止播放，歌词就会自动消失 —— 这是设计如此。
   服务端连续 10 秒收不到上报（浏览器被关掉、断网）也会自动让歌词消失，
   不会在屏幕上留一行「幽灵歌词」。

## 四、它到底连了什么（排查问题时看这一节）

服务端上就三个东西（都在虚拟桌面服务里，**不需要**额外开端口）：

| 接口 | 谁在用 | 认证 |
| --- | --- | --- |
| `POST /now-playing` | 浏览器（音乐播放器）上报 | 无（局域网内互相信任） |
| `GET /now-playing` | 本程序：连上后补一次画面；WebSocket 连不上时轮询兜底 | 无 |
| `WS /ws/lyrics` | 本程序：实时接收 | 无 |

★ 这三个路径**故意不在 `/api` 下**：悬浮窗是独立进程，没有登录会话的 Cookie，
而且要在没有人打开浏览器的深夜也能连上。代价是局域网内任何人都能推文字过来、
也能看到别人在放什么歌 —— 这是部署方式（班级局域网、互相信任）下接受的取舍。
将来要收紧的话，服务端 `config.json` 里有一个预留开关：

```json
"lyrics": { "enabled": true, "stale_seconds": 10, "token": "" }
```

给 `token` 配一个值，然后在本程序的「连接设置」里填同一个值即可，
其它任何东西都不用改。

## 五、多个人同时用

一台机器上可能有多个用户各自的音乐播放器（虚拟桌面是多用户的）。上报里带着
**用户名**，所以：

* 悬浮窗默认订阅「全部」：**谁在放就显示谁**（正在播放的优先于暂停的）；
* 实验室里几个人同时放歌时会互相顶掉 —— 这时在「订阅用户」里填**自己的用户名**
  （例如 `wangqi`），就只看自己的了。托盘菜单里能直接看到当前有谁在放歌。

## 六、配置与状态存在哪

```
%APPDATA%\桌面歌词\config.json
```

包括服务器地址、订阅用户、token、悬浮窗位置与大小、字号、穿透/锁定开关、
开机自启。**不在程序目录里**：装到 `Program Files` 之后那里是只读的，而且
每台机器的服务器地址本来就不一样。删掉这个文件 = 恢复出厂设置。

悬浮窗位置会自动记住（拖完松手即保存）。如果上次是拖到副屏、这次副屏没插，
它会自动回到主屏底部居中 —— 不会变成一个「看不见也拖不动」的窗口。

## 七、出问题时先看这里

| 现象 | 原因与处理 |
| --- | --- |
| 托盘图标在，但一直不显示歌词 | 先看托盘提示：它会写「已连接 / 连不上服务端 / 服务端已关闭该功能」。也可以在「连接设置」里点**测试连接**，它会直接告诉你原因 |
| 提示「服务端已关闭桌面歌词功能」 | 服务器 `config.json` 里 `lyrics.enabled` 是 `false`，改成 `true` 后重启服务 |
| 提示「服务端要求 token」 | 服务器配了 `lyrics.token`，把同一个值填到「连接设置」里 |
| 提示「WebSocket 连不上，已改用轮询」 | 网络设备/安全软件拦掉了 WebSocket。**歌词仍然能用**，只是慢一拍；想彻底解决要放行 `ws://服务器:8000/ws/lyrics` |
| 有歌在放，但歌词是歌名不是歌词 | 那首歌没有**带时间轴**的 `.lrc`（只有纯文本歌词，或者没有歌词）。在播放器里点「上传/编辑」加一份 `.lrc` |
| 歌词比声音慢/快半拍 | 播放器和服务端在同一台机器时基本不会出现；先确认两边时间正常。歌词本身的时间轴误差需要改 `.lrc` 文件 |
| 游戏里不显示 | 游戏是独占全屏，改成「无边框窗口化」，见第三节 |
| 拖不动 | 「鼠标穿透」开着（此时窗口收不到鼠标事件），先在托盘里关掉它 |
| 想彻底重置 | 退出程序，删除 `%APPDATA%\桌面歌词\config.json`，重新启动 |

日志：以 `npm start` 运行时，主进程的日志直接打在控制台；打包后的程序可以在
「连接设置」里点**测试连接**来获得同样的诊断信息。

## 八、开发与自测

```bat
npm start                             :: 运行
npx electron tools\smoke.js           :: 冒烟测试：用真 Electron 渲染 5 个场景，断言 DOM 并截图
```

`tools\smoke.js` 会把窗口按「播放中 / 暂停 / 前奏 / 调整模式 / 连不上」五种
情形各渲染一次，断言 DOM 里的那一行字是否正确，并把截图写到 `dist-smoke\`。
它验证的正是最容易出错的地方：窗口参数 + preload 通道 + 渲染层的接缝，
以及**透明窗口真的是透明的**（截出来的 PNG 带 alpha 通道：桌面区域全透明，
字是纯白填充 + 纯黑描边；暂停那张的最大 alpha 正好是 140 ≈ 0.55×255）。
全部通过会打印 `Ran 5 scenes, 0 failed`。

> 在没有交互桌面的机器（例如以服务/远程会话身份运行）上，Electron 可能因为
> 拿不到桌面而启动失败。可以加参数试：
> `npx electron --no-sandbox --disable-gpu tools\smoke.js`。

`tools\preview.html` 可以直接用浏览器打开：它加载**真实的** `overlay.css` 与
`overlay.js`，只是把主进程接口换成了页内的假实现。用来核对字号、描边、
换行动画这些外观细节很方便（`?scene=playing|paused|intro|empty|offline|long`）。

前端逻辑的用例在仓库根目录：

```bat
cd ..
node tests\js\desktop-lyrics-client.test.mjs    :: 连接层：重连/退避/轮询兜底
node tests\js\desktop-lyrics-overlay.test.mjs   :: 渲染层：时间与歌词行的对应
```

这两份用例都不需要 Electron，用 node 直接跑（连接层那份会真的起一个
WebSocket 服务端来测重连）。

### 换个图标

图标源图是 `build\icon.png`（256×256）。它是由一段 HTML/CSS 用无头浏览器渲染
出来的（渐变圆角方块 + 白色音符），改配色只要改 CSS 再渲染一次。生成
`.ico` 与托盘图标的脚本在仓库根目录：

```bat
cd ..
python tools\make_lyrics_icon.py
```

## 九、目录结构

```
desktop-lyrics/
├─ package.json            依赖、启动脚本、electron-builder 打包配置
├─ build/
│  ├─ icon.png             图标源图（256×256）
│  └─ icon.ico             打包用（含 16/24/32/48/64/128/256 七档）
├─ src/
│  ├─ main.js              主进程：悬浮窗、托盘、自启、位置保存
│  ├─ client.js            连接层：WebSocket + 重连退避 + 轮询兜底
│  ├─ store.js             本地配置（%APPDATA%）
│  ├─ preload.js           渲染进程与主进程之间唯一的通道
│  ├─ assets/tray.png      托盘图标（含 @2x）
│  └─ renderer/
│     ├─ index.html        悬浮窗页面
│     ├─ overlay.css       一行大字 + 黑描边 + 暂停半透明
│     ├─ overlay.js        时间外推、二分找当前行、尽量不碰 DOM
│     ├─ settings.html/css/js   连接设置窗口
└─ tools/
   ├─ smoke.js             冒烟测试（真 Electron）
   └─ preview.html         外观预览（浏览器直接打开）
```
