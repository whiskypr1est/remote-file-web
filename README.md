# 远程文件管理（Windows 桌面风格 Web 应用）

在浏览器里像操作本机 Windows 一样浏览和管理服务器文件。

后端 **Python + FastAPI + uvicorn**，前端 **原生 HTML/CSS/JavaScript + winbox.js 窗口系统**，
不依赖 Node.js、不需要任何前端构建步骤，window 端所有第三方库（winbox.js / pdf.js / xterm.js / CodeMirror）都已内置到
`static/vendor/`，**局域网内即使完全不通外网也能正常使用**。

## 一、功能特性

### 桌面与窗口
- 仿 Windows 10 桌面：全屏蓝色渐变壁纸（可自定义）、桌面图标、底部任务栏
- 任务栏：开始按钮（含「文件资源管理器 / 各根目录 / 关于 / 更换壁纸 / 注销」）、已打开窗口按钮（点击切换或最小化）、系统托盘（服务器地址 + 实时时钟 + 日期）
- 窗口基于 winbox.js：拖动标题栏移动、四边四角缩放、最小化、最大化/还原、关闭、多窗口层叠、点击置顶
- 双击标题栏最大化/还原、双击图片预览切换适应窗口/原始大小
- 窗口最大化会精确停在任务栏上方（不会盖住任务栏）
- 支持地址栏深链接：`#explorer/根标识/路径`、`#preview/根标识/路径`，可收藏或分享给同事
- **虚拟桌面快捷方式**：在资源管理器里右键文件夹/文件 →「发送到桌面快捷方式」，
  桌面就会出现带小箭头角标的图标。快捷方式**只存在于这个 Web 虚拟桌面**，
  不会往 Windows 真实桌面写任何东西；数据由服务端持久化
  （`desktop_shortcuts.json`），**重启服务、换浏览器、清缓存都不会丢**。
  桌面右键快捷方式可「打开 / 打开所在位置 / 重命名 / 删除快捷方式」，
  目标被移走或 U 盘拔出时会自动标灰划掉并给出提示
- **全盘访问**：默认自动挂载本机所有磁盘（C:/D:/E:…），「此电脑」里直接就能看到，
  不再局限于单个共享目录；插上 U 盘重启服务即自动出现

### 文件资源管理器
- **地址栏**：面包屑导航 + 可点击切换为输入框，支持直接粘贴绝对路径回车跳转
- **工具栏**：后退、前进、向上、刷新
- **视图切换**：图标视图（含图片缩略图）/ 详细列表视图（名称、修改日期、类型、大小，点表头排序）
- **多选**：单击、Ctrl+单击、Shift+范围选择、Ctrl+A 全选、Esc 取消
- **双击**文件夹进入，双击文件按类型打开预览窗口
- **「此电脑」视图**：展示所有可访问根目录及磁盘容量条
- 文件图标按扩展名区分：文件夹、图片、文档、演示文稿、PDF、压缩包、视频、音频、表格、代码、其他
- 右侧按钮区 + 右键菜单 + 键盘快捷键（F2 重命名、Delete 删除、F5 刷新、Backspace 向上、Enter 打开）
- 右键菜单对文本类文件还有**「编辑」**：在带语法高亮的编辑器窗口里直接改服务端的文件
  （保存用 `Ctrl+S`；只读根目录下该项置灰）。详见[编辑文本文件](#编辑文本文件)

### 文件操作
- **新建文件夹 / 新建文件**：新建文件时**扩展名由你自己选** —— 对话框里有常用类型下拉
  （`.txt` / `.md` / `.py` / `.js` / `.json` / `.yml` / `.csv` …），也可以直接在文件名里
  敲任意后缀（例如 `.tsv`），或者干脆不要扩展名。同名文件一律**拒绝**（409），
  绝不覆盖已有内容；扩展名黑名单与上传共用，因此默认建不了 `.bat` / `.ps1` 这类可执行文件
- 重命名（就地编辑，自动选中主文件名不含扩展名）、删除（**默认进系统回收站，可恢复**）
- **复制 / 剪切 / 粘贴**：`Ctrl+C` / `Ctrl+X` / `Ctrl+V`，或右键菜单；支持跨盘（C: → D:）复制与移动
- **拖动**：把文件/文件夹拖到文件夹图标上＝移动进去，按住 `Ctrl` 拖动＝复制；
  支持在多个资源管理器窗口之间拖动；被剪切的项目显示为半透明，粘贴后恢复
- 粘贴遇到同名文件**自动改名**（`报告.docx` → `报告 (1).docx`），**永不覆盖**已有文件
- 上传：支持文件选择与**拖拽上传**，单个文件最大 2GB，实时进度条，重名自动改名
- 下载：单文件直接下载；多选自动在服务器端打包成 ZIP 后下载
- 删除前弹确认框，删除失败会如实告知原因
- **压缩 / 解压**：右键「压缩…」可打包成 `zip` / `tar` / `tar.gz` / `7z` / `rar`；
  右键压缩包可「解压到当前文件夹」或「解压到 <包名> 文件夹」

> **不能**把文件从浏览器里拖到真实的 Windows 桌面 —— 这是浏览器的安全限制，
> 拖动只在「这个 Web 虚拟桌面内部」有效。
>
> 复制/移动是**同步**执行的（与「打包下载」一致）：选中几十 GB 时请求会等待较久，
> 期间界面会显示忙碌状态。

#### 压缩与解压

| 格式 | 创建 | 解压 | 依赖 |
| --- | --- | --- | --- |
| `.zip` | ✅ | ✅ | 无（标准库） |
| `.tar` / `.tar.gz` / `.tgz` / `.tar.bz2` / `.tbz2` / `.tar.xz` / `.txz` | ✅ | ✅ | 无（标准库） |
| `.gz` / `.bz2` / `.xz`（**单个文件的压缩流**，如 `app.log.gz`） | — | ✅ | 无（标准库） |
| `.7z` | ✅ | ✅ | `py7zr`（纯 Python，已随 requirements 安装） |
| `.rar` | ✅ | ✅ | WinRAR 的 `Rar.exe` / `UnRAR.exe`，自动探测安装目录 |

> 后缀决定真正的压缩方式，这一条有回归测试盯着（看的是**文件头魔数**，不是文件名）。
> `.tgz` / `.tbz2` / `.txz` 这些别名也都在覆盖范围内 —— 它们并不以 `.gz`/`.bz2`/`.xz` 结尾，
> 只按后缀结尾判断会把它们漏掉、产出「没压缩的 tar 却叫压缩包」，实测踩过这个坑。
>
> 裸 `.gz`/`.bz2`/`.xz` 有两种可能：包着 tar（`.tar.gz`）或只压了一个文件（`app.log.gz`）。
> 会先按 tar 试，打不开就退到单文件流，解成 `app.log`。

- 压缩包**生成在服务器上**（不是下载），默认放在源文件旁边；重名会自动改名，
  不会覆盖已有的压缩包。
- 解压目标若已存在同名项则**整体拒绝**并列出冲突的名字 —— 解压是批量写入，
  一旦覆盖几乎没有恢复手段，所以宁可让你换个目录重来。
- 中文文件名兼容：Windows 自带「发送到 → 压缩(zipped)文件夹」生成的是
  GBK 名字且未置 UTF-8 标志位，解压时会自动还原（仅在确实解出中日韩字符时才改写，
  不会把西欧语言的合法文件名弄坏）。
- 解压有防「解压炸弹」上限，见配置 `archive` 段；RAR 相关能力需要 WinRAR，
  未安装时会明确提示而不是静默失败。
- **加密压缩包（带密码）暂不支持**：会明确告诉你「需要密码才能解压」，
  而不是抛一个看不懂的服务器内部错误。创建压缩包也不支持设密码。
- 打包时**不会跟进符号链接与目录联接**（junction）：Windows 上
  `os.path.islink()` 认不出目录联接，一旦跟进就会把联接指向的外部内容一起装进包里。
  被跳过的项会在结果里如实列出。创建 RAR 时另加了 `-ol`，因为 RAR 有自己的遍历逻辑。

### 编辑文本文件

文本预览的工具栏上有**「编辑」**按钮，资源管理器里右键文件也有**「编辑」**，
都会另开一个带语法高亮的编辑器窗口（CodeMirror 5，本地内置）。

**会高亮的扩展名**（其余文本按纯文本打开，一样能改）：

| 语言 | 扩展名 |
|---|---|
| Python | `.py` |
| Shell | `.sh` `.bash` |
| 批处理 | `.bat` `.cmd` |
| PowerShell | `.ps1` |
| JavaScript | `.js` `.mjs` |
| JSON | `.json` |
| HTML / XML | `.html` `.htm` `.xml` `.svg` |
| CSS | `.css` |
| Markdown | `.md` |
| YAML | `.yml` `.yaml` |
| SQL | `.sql` |
| ini / properties | `.ini` `.cfg` `.conf` `.properties` |
| 纯文本 | `.txt` `.log` `.csv` |

- **`Ctrl+S` 保存**，也可以用工具栏的「保存」按钮；标题栏出现 `●` 表示有未保存的改动。
- **「还原」**重新从磁盘读一遍，放弃当前改动（会先确认）。
- **带未保存改动关窗口会先问一句**，选「取消」窗口就留着。
- 编码（UTF-8 / GB18030 / Big5…）、BOM、换行符（CRLF / LF / CR）都会**原样保留**：
  读的时候服务端告诉你原来是什么，保存时按原样写回去，不会把 CRLF 文件悄悄变成 LF。

#### ⚠️ 两条必须知道的安全行为

1. **文件太大时不能在这里改。**
   预览和编辑器都只读文件的前 `preview.text_max_kb`（默认 2048KB）。
   超过这个上限的文件，编辑器会用一层遮罩**锁成只读**并写明原因 ——
   因为缓冲区里只有前半段，一旦保存就等于把后半段删掉，而界面上看不出来。
   要改这种文件请走：**下载 → 本地编辑 → 上传覆盖**。
2. **文件在别处被改过时，保存会被拒绝。**
   打开文件时会记住当时的修改时间和大小；保存时服务端会比对磁盘现状，
   不一致就直接返回 `409` 并**一个字节都不写**，然后给你一个**「重新载入」**。
   这样就不会覆盖掉别人的修改（或者你自己另一个窗口里的修改）。
   重新载入会丢弃你当前的改动，所以那一步由你按下去，程序不会自作主张。
   顺带一提：保存成功后会立刻刷新这份凭据，所以**连续保存第二次**不会误报冲突。

### 命令行（CMD）窗口
- 任务栏「开始」菜单 →「命令提示符」，或桌面右键 →「新建命令提示符窗口」
- **是真正的终端**：后端用 ConPTY（pywinpty）给 shell 分配伪控制台，前端用 xterm.js 渲染，因此：
  - 裸 `python` 能正常进入交互式解释器（出现 `>>>`），`node`、`git`、`ipconfig` 等同理
  - **Tab 补全**、方向键翻历史、**`Ctrl+C` 真正中断正在运行的程序**
  - 窗口缩放会同步给远端（换行位置不会错行），彩色输出正常
  - **支持中文输入法打字**（xterm.js 内置能力），中文路径也可直接敲
- 工具栏：新建 / 清屏 / **中断** / **断开** / **结束会话**（后两个是**不同**的动作，别混）
  - **断开** = 走开：会话在服务端继续跑，输出继续攒，之后还能接回来（窗口里会出现「重新连接」）
  - **结束会话** = 真的关掉：发 `{"type":"close"}`，杀掉整棵进程树，**之后接不回来**。
    所以它需要**二次确认**（不可逆的操作不该挨着随手点的按钮）
  - `Ctrl+C` 是**原生中断**（和真机一样），优先用它
  - 「中断」按钮是**逃生口**：杀掉卡住的子进程但**保留 shell**，
    当前目录还在，适合程序赖着不走时救场
- 工作目录在命令之间保持；默认最多 4 个并发会话，空闲 30 分钟自动关闭
- **关掉浏览器不等于结束会话**：断开连接只是「离开」，`cmd.exe` 继续跑、
  输出继续进缓冲；重新打开页面会用同一个会话 id 接回去，先补上离开期间错过的输出。
  真正结束会话只有三种情况：空闲超时、显式关闭、服务退出。
  这样「浏览器崩了 / 手滑关了标签页」不会把正在跑的任务一起带走。
  - 会话可分离之后 `max_sessions` 更要紧：分离的会话**仍然占名额**（它确实还占着一个 shell），
    所以撞到「会话数已达上限」时，请把不再需要的命令行窗口关掉，或等空闲回收
  - 重连时会话已被回收的话会明确提示「会话已结束」，而不是静默卡住

### 会话持久（关掉页面再打开还是之前的界面）

- 打开的**资源管理器 / 预览**窗口、它们的位置与尺寸、最大化状态、
  每个资源管理器窗口所在的目录与视图模式、以及前进后退历史，
  都会保存到服务端，重新打开页面时原样恢复
- 状态存在 `user_state_path`（默认项目根目录下的 `user_state.json`），
  与 `desktop_shortcuts.json` 同级，方便一起备份
- ★ 多用户下**按用户分开存**：管理员用 `user_state.json`，
  子用户各用 `user_state.<用户名>.json`（快捷方式同理）—— 否则同学刷新页面
  看到的会是你的窗口布局
- 保存是**整体覆盖**（前端每次手握完整布局），并做了防抖，拖动窗口不会刷爆服务端；
  单次上限 256KB
- 恢复是**容错**的：某个窗口记的目录已经被删除或盘符没挂上，只会跳过那一个，
  不会导致整个桌面打不开；损坏的状态文件会被当作「没有状态」处理
- 想恢复默认布局，删掉对应的那份状态文件再刷新即可（不影响快捷方式）
- 若目标机器没装 `pywinpty`，会自动**退回管道模式**并在窗口里提示：
  功能仍可用，但上面那些交互能力（交互式程序 / Tab 补全 / Ctrl+C 中断 / 缩放）都没有

> ### ⚠️ 安全警告（请务必阅读）
> 这个功能**等于把服务器的命令行交给任何能登录本服务的人**。
> 以 Windows 服务方式（NSSM）运行时进程身份是 **SYSTEM**，即最高权限；
> 而本服务默认走明文 HTTP，局域网内密码是明文传输的。
> 不需要这个功能时，请把 `config.json` 里的 `terminal.enabled` 改成 `false`（默认是 `true`）。
>
> 另外，真终端下**全屏交互程序（如 `vim`）也可能被跑起来**，
> 这比原来的管道模式能做的事情更多，请务必按上面的建议评估是否开启。

### 任务管理器（性能与进程）

任务栏「开始」菜单 →「任务管理器」，或桌面右键 →「打开任务管理器」。

仿 Windows 任务管理器：上半部分是**性能卡片**，下半部分是**进程表**。

| 卡片 | 内容 |
|---|---|
| CPU | 总占用率、每个逻辑核一根细条、主频、逻辑/物理核数、负载均值、CPU 型号 |
| 内存 | 已用 / 总量、使用率、可用量、交换分区 |
| 磁盘 | 本机所有磁盘的合计读 / 写速率 |
| 网络 | 总计上 / 下行速率、累计流量，以及当前有流量的前几块网卡 |
| GPU | 利用率、显存占用、温度；**读不到时会说明原因，而不是显示 0%** |

进程表按 CPU 或内存**降序**显示前 N 个（默认 30，可配），点表头即可切换排序维度；
每行显示 名称 / PID / CPU / 内存% / 内存 / 用户 / 状态，服务端自己的进程标为「（本服务）」。

- 刷新间隔可选 1 / 2 / 5 / 10 秒，也可以随时「暂停」；页面**切到后台时自动停止轮询**，
  切回来立刻补一次，不必空转
- 进程 CPU 占比已**归一化到整机**，口径与 Windows 任务管理器一致
  （8 核跑满 4 核显示 50%，而不是 400%）
- 服务端刚启动后的**第一轮**进程 CPU 必然全是 0（psutil 要先建立一个基线才能算差值），
  界面会提示「首次采样中」，第二轮起就是真实值
- **只读，不提供「结束进程」**：真要动进程请用命令行窗口（那本来就是个真终端）。
  一个能按 PID 杀进程的 HTTP 接口，风险与收益完全不成比例
- **不参与布局持久化**：任务管理器窗口不会被写进 `user_state.json` ——
  否则每次打开页面都会自动弹出一个正在轮询的监控窗口
- **GPU 仅在 NVIDIA 上可用**：通过 `nvidia-smi` 读取。Intel / AMD 显卡需要
  Windows PDH 性能计数器，尚未实现，此时卡片会明确显示「不可用」并说明原因
- 不需要时把 `config.json` 的 `sysmon.enabled` 改成 `false`：开始菜单与桌面右键的
  入口都会消失，`/api/sysmon/snapshot` 也会返回 403

> 进程列表会暴露服务器上正在运行哪些程序、以及各自属于哪个用户。
> 它只是只读信息，但如果这属于你不愿公开的信息面，请关掉 `sysmon.enabled`。

### 音乐播放器

开始菜单 →「音乐播放器」。仿 QQ 音乐的三栏布局：左边是我的歌单，中间是歌曲列表，
右边是带**逐句高亮**的歌词，底部是播放条。

- **导入**：工具栏「导入歌曲」会列出**你能看到的目录**（与文件管理器同一套可见性
  规则），进去勾选音频文件即可。导入是**复制**一份到曲库，源文件不动 ——
  这样删歌单/清曲库不会伤到你原来的文件。
- **上传**：也可以直接选本机文件上传（带进度）。
- **批量勾选**：列表每行前面有勾选框，表头那个是全选（只作用于当前列表里看得见的
  那些，所以先搜索再全选也好使）。勾上之后顶部会出现**批量操作条**：
  「加入歌单 / 从曲库移除」（在歌单里还有「移出歌单」）以及「反选 / 取消选择」，
  一次处理几十首不用一首首点。
  ★ **刚导入 / 刚上传的歌会自动勾上** —— 导入完直接点「加入歌单」就能整批归类，
  这正是最常见的下一步。
- **歌单**：新建、重命名、删除；在列表里点「加入歌单」把歌塞进去，歌单里的
  顺序就是你加入的顺序。**歌单按人分开存**，同学看不到也改不了你的。
  重命名 / 删除有两个入口：鼠标移到歌单上会出现铅笔和垃圾桶图标（**当前选中的
  那个歌单始终显示**），或者在歌单上**点右键**选择。
- **歌词**：导入时会**自动识别**与歌曲同名的 `.lrc` 并一起带走；也可以在右侧
  面板里「上传 .lrc」或直接「编辑」粘贴。支持 `[mm:ss.xx]` 时间标签，
  会随播放逐句高亮并自动滚到中间，**点某一句可以跳到那一句**。
- **播放**：上一首 / 下一首 / 播放暂停，右上角切换四种模式 ——
  **列表循环 / 单曲循环 / 顺序播放 / 随机播放**；进度条可拖动（服务端支持 Range），
  音量可调并**按人记住**（我把音量调到 10% 不会影响别人的耳朵）。
  空格键播放/暂停，`Ctrl+←/→` 切歌。
- 曲库就是**文件系统里的一个目录**（默认项目根目录下的 `music/<用户名>/`），
  所以歌曲在文件管理器里看得见、能备份、能直接用别的播放器打开。
  改成全机共用把 `music.per_user` 设成 `false` 即可。
- **窗口会被持久化**（和资源管理器 / 终端 / 预览一样）：关掉浏览器再打开，
  播放器还在原来的位置和大小，上次听的那首歌也摆好了（暂停状态，按一下播放键接着听）。
  听到第几秒不还原 —— 与常见播放器一致。

> 只接受**浏览器能真正播放**的格式：mp3 / flac / m4a / aac / ogg / opus / wav / webm。
> wma、ape、midi、aiff 这些浏览器解不了，导入时会被明确拒绝并说明原因 ——
> 收下放不出来的文件，只会让人以为播放器坏了。
>
> 也**不会**去解析音频文件里的专辑封面（那要自己写 ID3/FLAC 元数据解析），
> 封面用歌名散列出的渐变色 + 首字代替。列表里的时长由浏览器读元数据得到，
> 只探测当前视图的前 40 首、且是串行的（几百首一上来并发几十个请求会把服务端打难受）。

### 桌面歌词（独立悬浮窗客户端）

开音乐播放器放歌，歌词会以**一行大字浮在整个屏幕最上层**（仿网易云音乐的桌面
歌词：白色字 + 黑色描边），而且**关掉浏览器之后照样在**。暂停时整行变半透明，
停止播放或关掉播放器窗口后自动消失。

它不是网页的一部分，而是仓库里 `desktop-lyrics/` 那个**独立小程序**（Electron），
装在需要看歌词的机器上。之所以必须独立：网页只能在浏览器窗口里画东西，而桌面
歌词要浮在**所有**窗口之上、并且要在浏览器关掉后继续存在。

```
浏览器（音乐播放器）──每 0.5 秒上报──▶ 服务端（转发）──WebSocket 广播──▶ 悬浮窗
```

- **服务端只是转发**，不落盘、重启即忘（这是实时状态而不是数据）：播放器上报
  「现在在放什么」，服务端广播给所有订阅者。服务端这边**不需要额外配置、也不占
  额外端口**，和虚拟桌面同一个 8000 端口。
- **悬浮窗**：透明、无边框、置顶（`screen-saver` 层级）、不占任务栏、**鼠标穿透**
  （点到的还是下面的游戏/软件）、永不抢焦点。全部开关都在右下角**托盘菜单**里：
  显示/隐藏、鼠标穿透、锁定位置、字号（28/40/52/68）、进度条、订阅哪个用户、
  连接设置、**开机自启**、退出。拖动位置会自动记住。
- **多人同时用**：上报里带**用户名**，所以默认「谁在放就显示谁」；几个人同时放歌
  会互相顶掉，这时在托盘里把「订阅用户」设成自己的用户名就只看自己的了。
- **暂停时发心跳**：暂停后歌词不会消失（半透明留着），而浏览器被关掉/断网 10 秒后
  服务端会自动让大家隐藏歌词 —— 不会在屏幕上留一行「幽灵歌词」。

> ⚠️ **独占全屏的游戏盖不住这层字**（Windows 合成器的限制，Discord / Steam 的浮层
> 同样盖不住）。把游戏改成**「无边框窗口化」**即可，画面几乎没有区别。

安装与详细用法见 [`desktop-lyrics/README.md`](desktop-lyrics/README.md)：
在 `desktop-lyrics/` 里 `npm install` 后 `npm start` 直接跑，或 `npm run dist`
生成**安装版 + 便携版**的 exe（装好的机器不需要 Node）。

### 照片（时间轴相册）

开始菜单 →「照片」。照片按**拍摄时间**摊在时间轴上（年 / 月 / 日三档粒度可切换），
点开看大图，并且可以改时间、改地点、打标签、按时间段归类。

#### 与音乐播放器最大的不同：照片是**就地索引**，不复制

音乐播放器会把歌**复制**一份进曲库（一首歌几 MB，代价很小）。照片不能这样：
一个照片库动辄几十上百 GB，复制一份在时间和空间上都不可接受。所以照片
**只记录「文件在哪 + 它的元数据」**，原文件留在原来的位置、一个字节都不动。

代价是这个功能必须正面处理三件事：

- **文件会被移走 / 改名。** 每张照片都存一个**内容指纹**（文件**前 256KB** +
  大小做的 sha1，只读头部、几毫秒一张）。点「重新扫描」时按指纹把文件认回来 ——
  **你改过的时间与地点会跟着走**，因为编辑记录是按指纹存的，不是按路径。
  把照片从一个文件夹挪到另一个文件夹、或者改个名，整理成果不会白费。
- **文件会变。** 索引里存了大小与修改时间当凭据，读取时比对；对不上就标成
  「待刷新」，绝不用旧元数据装作没事（与文本编辑器保存前比对是同一个思路）。
- **设备可能不在线。** 移动硬盘拔了、盘符没挂上，那批照片会标成「找不到」并灰度
  显示，但**你的编辑记录一条都不会丢**；把设备接回来再扫一次就自动恢复。
  ★「文件暂时不在」从来不是删掉用户数据的理由。

#### 时间的三态：这是「按时间轴归类」能不能用的关键

一张照片「实际显示在时间轴的哪个位置」，按这个优先级算：

```
你手动设置的时间   ??   照片 EXIF 里的拍摄时间   ??   文件的修改时间
     (user)                  (exif)                    (file)
```

最后一档是**下载/保存时间，不是拍摄时间**。微信里保存的图、截图、从网上下载的
图片基本都没有 EXIF，它们会全部落到这一档 —— 时间轴看着挺满，其实一半的位置是错的。

所以界面必须把它显式标出来，这也是本功能里最要紧的一个设计：

- 网格里这些照片带一个**「待整理」角标**，并且轻微降饱和，一眼能分辨；
- 侧栏有专门的「**待整理（时间不可靠）**」入口，把「哪些还没修」变成一个有终点的清单；
- 编辑面板里会直说「这张的时间取自文件修改时间」；
- 改完之后角标消失、来源变成「你手动设置的时间」。

#### 编辑只改相册，**不动照片文件**

改时间、地点、标签、星级、备注，全部只写进服务端的 `photos_state.json`，
**原图一个字节都不改**（界面上也明确写着这一点）。

为什么不做「写回 EXIF」：那要重新编码整个 JPEG —— 画质会掉，还会丢掉厂商私有的
MakerNote；而这个项目一贯的取向是绝不静默覆盖原始资料。非破坏的另一个好处是
批量操作可以放开做，因为随时能撤销。

- **单张**：大图查看右侧面板直接改，保存后立刻生效。
- **批量**：选中多张（`Ctrl` 点选、`Shift` 范围选）→「编辑时间 / 地点」。
  最常用的是**整体平移**：相机的时区设错了、一次旅行拍的几百张全部偏 8 小时，
  整体挪一下就对了，**彼此的先后顺序保持不变**。
- **撤销**：工具栏常驻一个「撤销」，回退最近一次编辑（批量改错了不用一张张改回来）。
- **同一地点批量命名**：同一次拍摄的照片 GPS 坐标通常**完全一致**，所以发现一批
  同坐标的照片时会提示「把地名应用到全部」—— 一次输入解决几百张的「这是哪儿」。

#### 相册（按时间轴归类）

- **智能相册**：给一个时间段，落在这个范围里的照片自动归类进来（以后新导入的
  也会自动进来）。这是「通过时间轴对照片归类」最直接的用法。
- **手动相册**：自己挑照片放进去；右键或批量操作条里都能加入。
- **删相册 / 移出目录都不会删照片**：这类操作只动归类与编辑记录，
  照片文件本身一个都不会少（确认框里也明确写了这一点）。

#### 导入

「导入照片」会列出**你能看到的目录**（与文件管理器同一套可见性规则），
进去勾选文件夹即可，子文件夹会一起收录。照片多的时候可以走后台任务，
右下角任务面板里有进度条。

> **不会**跟随符号链接与目录联接（Windows 上 `os.path.islink()` 认不出目录联接，
> 跟进去会把根目录外的整棵树拖进来）—— 与打包、搜索是同一套判断。
>
> **`.heic` / `.heif` 看不了**：iPhone 的默认格式需要额外的解码器（`pillow-heif`），
> 本项目依赖里没有。导入时会**明确跳过并说明原因**，而不是收下一个打不开的文件。
>
> **不做地图**：离线环境下拿不到地图瓦片与地理反查，所以地点是「坐标 + 你填的名字」。
> EXIF 里的 GPS 会读出来、能按地点筛选，「同坐标批量命名」用来补偿没有反查这件事。

### 后台任务与进度（复制 / 移动 / 解压）

这三类操作可能跑很久，所以走**后台任务队列**：提交后立刻返回，进度显示在右下角的
**任务面板**里（进度条 + 已处理条目 / 体积 + 当前文件名），随时可以取消。

- **不再用整屏遮罩**：以前复制几十 GB 时那层转圈遮罩会把整个桌面锁住，用户既看不到
  进度、也没法继续做别的事。现在可以同时跑多个任务，也不挡着浏览文件
- **进度到字节级**：复制按 1MB 分块，所以「一个 20GB 的大文件」也能看到进度条在走
  （而不是从 0% 直接跳到 100%）；解压逐条目报进度
- **取消是协作式的**：点取消只是打标记，任务在下一个检查点停下 ——
  Python 没法安全地强杀一个正在写文件的线程，硬杀会留下写了一半的文件。
  所以面板会显示「正在取消…」直到真的停下
- **关掉浏览器不等于取消**：任务活在服务进程里、会继续跑完，重新打开页面时面板会把
  它们重新列出来；要停就得点取消（与命令行窗口的「断开 ≠ 结束会话」是同一个道理）
- 并发上限 2 个（几个大复制一起跑只会让每个都变慢，还会把磁盘随机 IO 打爆）；
  结束的任务保留 10 分钟供查询，之后自动回收
- **7z / RAR 的解压只有「开始 / 结束」两档进度**：它们走外部库的 `extractall`，
  中间过程观察不到。与其编一个假进度，不如如实显示

> 这三个接口的**默认行为没变**（仍是同步、请求挂到做完为止），后台模式由请求体里的
> `background: true` 开启，Web 界面默认开启它 —— 这样命令行脚本与既有调用方不受影响。
> 校验（只读根目录、路径穿越、重名冲突）仍然在提交那一刻同步完成，
> 不会把 4xx 降级成「任务失败」让用户过一会儿才发现。

### 压缩包在线浏览

右键压缩包打开预览，看到的是**内容目录表**（名称 / 原始大小 / 类型），
外加「当前文件夹里是否已有同名项」的提醒 —— 不必先解压到磁盘、看完再删掉。

条目名与真正解压落盘的名字**完全一致**（复用了解压流程的第一道安全闸门
`list_entries`），所以不会「列表里叫 A、解出来却叫 B」。加密包与损坏的包都会给出
可读的中文原因，而不是一个 500。条目很多时只列前 500 条，并如实标出总数。

### 文件搜索（开始菜单搜索框）

开始菜单顶部有搜索框，分两层互补：

- **本地即时过滤**：已经在菜单里的程序、根目录、桌面快捷方式，边打边筛、零延迟
- **服务端文件搜索**：满 2 个字符后（防抖 300ms）递归搜**文件名**，结果列在菜单下方，
  点一条就在资源管理器里打开它所在的目录

搜索有**三重刹车** —— 结果数 / 扫描条目数 / 时间预算（默认 100 条、20 万条目、8 秒）。
任一触发都会跟着已有结果返回并标记被截断，而不是让请求挂死；开了
`mount_all_drives` 之后这就是「全盘搜索」，不设限能把服务占住好几分钟。
不跟进符号链接与目录联接（否则可能成环走不出来）。**只搜文件名，不搜内容**。

### 在线修改密码

开始菜单 →「修改密码」，或桌面右键 →「修改密码…」。改完**只有你自己**已登录的
设备会退出（包括当前浏览器），需要用新密码重新登录 —— 别人的会话不受影响。

另外，改密码**必须验证当前口令**：只看会话是不够的，Cookie 一旦被窃取，
攻击者就能改掉口令把管理员永久锁在外面。

### 资源管理器的键盘导航

- `↑` `↓` 移动选择（图标视图按「一行几个」跳，列表视图逐个跳）
- 图标视图下 `←` `→` 逐个移动；列表视图下左右键不参与选择（与 Windows 一致）
- `Shift + 方向键` 扩展选区，`Home` / `End` 跳到首尾，`PageUp` / `PageDown` 翻页
- **首字母跳转**：直接敲字符就跳到下一个以它开头的条目；连续敲入会拼成前缀
  （停手 800ms 后重新开始），所以敲 `re` 会跳到 `report.txt`，而不是只按 `r` 找一个
- 移动选择时自动把目标滚进视野；正在就地重命名时不会抢按键

### 多用户（管理员 / 学生）

一台机器可以给多个人用：一个**管理员**（导师）+ 若干**子用户**（学生）。

- **子用户只看得见分给他的目录**。他的「此电脑」就是那几个文件夹，
  看不到任何磁盘、也看不到同学的目录。可见目录在管理界面里按行填写
  （`路径 | 名称 | 只读`，第三段可省略；标了只读的目录只能读不能改）。
- **管理员**照旧看得到全机（`mount_all_drives` 那套行为完全没变），
  并且多出一个开始菜单入口 →「**用户管理**」：建账号、改显示名/角色/
  可见目录/命令行名额、重设口令、**停用**、强制下线；另有「在线」与
  「审计日志」两个标签页。
- **停用而不是删除**：停用会让他手里的会话**立即**失效且在重新启用前无法登录，
  但**不动他的文件**，也不切断「这个人是谁」的审计线索。
  数据安全优先 —— 要彻底删账号请手工编辑 `users.json`。
- 子用户的命令行窗口名额是**每人 5 个**（可在用户管理里单独调），另有全机总量兜底；
  并且**别人名额满了只会顶掉自己的闲置窗口**，绝不会杀掉同学正在跑训练的 cmd。
  关掉浏览器后 cmd 会一直留着（`idle_timeout_seconds = 0`），方便回来接着看输出。
- 「命令提示符」与「任务管理器」可以**按人**关掉（用户管理 → 编辑 → 权限）。
  关掉之后接口也会真的返回 403 —— 不是只藏起按钮。
- 界面状态（窗口布局、桌面快捷方式）**按用户分开存**，所以「关掉页面再打开
  还是原来的桌面」拿到的是自己那份，不会被同学覆盖。

管理员能看到的运行时信息是**计数**：某人几个命令行窗口、几个进程、几个后台任务、
在线与否（IP / 最后活动时间）。**看不到终端输出内容** —— 那是刻意的。

> ⚠️ 动手之前请先读 [MULTIUSER.md](MULTIUSER.md) 第〇节：子用户拿到的是**全权限命令行**，
> 所以「子用户只能看到自己的文件夹」是**界面与接口层面的便利，不是安全边界**。
> 他们能看到同学的文件（用 cmd 或直接粘绝对路径之外的路径）、能读 `users.json`、
> 能结束别人的进程。这是与使用场景（同机同组学生、机器本来就在他们手上）
> 一起明确确认并接受的风险。
> 若需要真正的隔离，必须给每个用户单独开 Windows 账号、并用低权限身份运行服务，
> 那是另一个量级的工程。

## 四、快速开始（Windows）

### 1. 安装依赖

在项目目录下打开命令行（PowerShell 或 CMD）：

```bat
:: 建议使用虚拟环境，避免污染系统 Python
python -m venv .venv
.venv\Scripts\activate

pip install -r requirements.txt
```

> **提示**：`start.bat` 会优先使用项目目录内的 `.venv`。
> 如果是别人**整个目录打包交付**给你（可能已预置 `.venv`，实测约 60MB），

>
> 但**从本仓库 clone 下来的目录不含 `.venv`**（已在 `.gitignore` 中排除），必须自己建。
> 见下方命令，或删掉已有的 `.venv` 后重建。

如果 pip 下载慢，可换国内镜像：

```bat
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

双击 `start.bat`，或在命令行执行：

## 五、配置详解 config.json

完整字段说明（也可以参考 `config.example.json`）：

```jsonc
{
  "server": {
    "host": "0.0.0.0",        // 0.0.0.0 = 监听所有网卡，局域网可访问；127.0.0.1 = 仅本机
    "port": 8000,             // 服务端口
    "title": "远程文件管理"    // 页面标题与「关于」里显示的名称
  },

  "roots": [                  // 允许访问的根目录，可以配置多个（可留空，见下方自动挂载）
    {
      "id": "share",          // 前端使用的稳定标识（改名不影响已有书签）
      "name": "共享目录",      // 桌面图标 / 开始菜单里显示的名字
      "path": "D:\\Share",    // 实际目录；不存在时启动会自动创建
      "readonly": false       // true = 该目录只读，禁止新建/上传/改名/删除
    }
  ],

  // ★ 自动把本机所有磁盘（C:/D:/E: …）挂载为可访问根目录。
  // 打开后「此电脑」里能直接看到所有盘符；以后插入 U 盘/移动硬盘，
  // 重启服务会自动出现，不用再改配置。
  "mount_all_drives": true,
  // 是否也挂载网络驱动器（网络盘无响应时可能让界面卡顿，默认关闭）
  "mount_network_drives": false,
  // 是否挂载可移动磁盘（U 盘、移动硬盘）
  "mount_removable_drives": true,

  // ★ 受保护路径：允许浏览，但禁止新建/重命名/删除/上传。
  // 开放整盘访问后这道保险很有用 —— 误删这些目录可能让 Windows 直接起不来。
  // 想完全放开就改成空数组 []。
  "protected_paths": [
    "C:\\Windows",
    "C:\\Program Files",
    "C:\\Program Files (x86)",
    "C:\\ProgramData",
    "C:\\$Recycle.Bin",
    "C:\\System Volume Information",
    "C:\\Recovery",
    "C:\\PerfLogs"
  ],

  "auth": {
    "username": "admin",
    "password_hash": "pbkdf2_sha256$260000$...",  // 推荐：只存哈希
    "password": "",                                // 兼容项：明文（不推荐，启动会告警）
    "session_secret": "自动生成的随机串",           // 会话签名密钥，不要外泄
    "session_hours": 12,                           // 登录状态保持时长
    "max_login_fails": 5,                          // 连续失败几次后锁定
    "lockout_seconds": 300,                        // 锁定时长（秒）
    // ★ 可信反向代理。X-Forwarded-For 是客户端可随意伪造的头，
    // 只有直连对端 IP 命中这个列表时才采信它来判定客户端 IP
    // （登录失败锁定按该 IP 计数）。默认空数组 = 完全不信任该头。
    // 前面挂了 Nginx/Caddy 时填代理所在机器：["10.0.0.5"] 或 ["10.0.0.0/8"]
    "trusted_proxies": []
  },

  "ui": {
    "wallpaper": "",          // 空 = 内置蓝色渐变；也可填 /static/wallpapers/xxx.jpg
    "default_view": "list"    // 新建窗口默认视图：icons | list（本项目默认 list）
  },

  "upload": {
    "max_file_size_mb": 2048, // 单文件上限（2GB）
    "blocked_extensions": [   // ★ 禁止上传的可执行文件扩展名，按需增删
      ".exe", ".com", ".scr", ".pif", ".cpl", ".msi", ".msp",
      ".bat", ".cmd", ".ps1", ".psm1", ".psd1", ".vbs", ".vbe",
      ".wsf", ".wsh", ".hta", ".reg", ".inf", ".msc", ".sct",
      ".dll", ".sys", ".drv", ".ocx", ".gadget", ".job", ".lnk",
      ".appx", ".msix", ".appxbundle"
    ]
  },

  "delete": {
    "use_recycle_bin": true   // true = 删除到系统回收站（可恢复）；false = 永久删除
  },

  // ★ 虚拟桌面里的「命令提示符」窗口
  // 等于把服务器命令行交给任何能登录本服务的人；以服务方式运行时身份是 SYSTEM。
  // 不需要就改成 enabled: false（改完重启服务生效）。
  "terminal": {
    "enabled": true,            // 是否启用命令行窗口（默认开）
    "shell": "cmd.exe",         // 也可换成 powershell.exe
    // ★ 每人同时允许开几个命令行窗口（多用户下按用户计，不是全机）
    "max_sessions": 5,
    // 全机总量兜底（0 = 不设限），防「每人 5 个 × 很多人」
    "max_sessions_total": 64,
    // ★ 空闲多久自动关闭（0 = 不限制）。多用户下定为 0：关掉浏览器后
    // cmd 一直留着，方便回来接着看输出；总量靠上面两个上限管住。
    "idle_timeout_seconds": 0,
    "max_output_kb": 512,       // 单会话在浏览器侧保留的输出上限
    // 会话上限满了之后，一个「没有客户端连着且已闲置这么久」的旧会话
    // 可以被新会话顶掉，而不是直接报「会话数已达上限」（秒）。
    // ★ 顶替只发生在**同一个人**的会话之间 —— 别人满员不会杀掉你的窗口。
    "evict_grace_seconds": 20,
    "start_dir": ""             // 启动目录，留空 = 第一个可访问根目录
  },

  "thumbs": {
    "enabled": true,          // 是否生成图片缩略图
    "cache_dir": "./thumb_cache",
    "size": 100,              // 缩略图边长（像素）
    "max_cache_mb": 512       // 缓存体积上限，超出按最旧优先清理
  },

  "office": {
    "enabled": true,          // 是否启用 Office 预览
    "soffice_path": "",       // 留空自动探测 LibreOffice；也可写死 soffice.exe 完整路径
    "timeout_seconds": 120,   // 单次转换超时
    "cache_dir": "./office_cache",
    "max_cache_mb": 1024      // 转换结果缓存体积上限（MB），超出按最旧优先清理
  },

  // ★ 多用户：这两个值是**管理员**用的那份文件（沿用原名，升级前后不变）。
  //   子用户各自落在同目录的 user_state.<用户名>.json /
  //   desktop_shortcuts.<用户名>.json —— 否则多人共用一个文件会互相覆盖对方桌面。
  //   判据是角色而不是名字：管理员改了登录名也仍然用这两个基础文件。
  "user_state_path": "user_state.json",        // 界面状态（窗口布局）存哪儿，相对路径相对本文件
  "desktop_shortcuts_path": "desktop_shortcuts.json",  // 桌面快捷方式存哪儿

  // ★ 审计日志：登录成功/失败、登出、改密码、账号增删改停用等**账号层面的动作**
  //   落盘留痕（一行一个 JSON）。刻意不记录文件浏览/上传下载这些高频动作 ——
  //   那会把日志淹掉。写失败绝不影响业务（磁盘满也不该让人登不进来）。
  "audit": {
    "path": "audit.log.jsonl",  // 相对路径同样相对本文件；多实例各记各的
    "max_bytes": 4194304,       // 单文件上限，超出后轮转成 .1 / .2 / …
    "backups": 3                // 保留几份历史（0 = 不保留）
  },

  "archive": {
    "max_entries": 20000,     // 单个压缩包最多多少个条目，超出拒绝解压
    "max_total_mb": 8192,     // 解压后总体积上限（MB）
    "max_single_mb": 4096,    // 解压后单个文件上限（MB）
    "rar_path": "",           // Rar.exe 完整路径，留空自动探测 WinRAR 安装目录
    "unrar_path": ""          // UnRAR.exe 完整路径，同上
  },

  // ★ 虚拟桌面里的「任务管理器」窗口（只读监控，不含结束进程）
  "sysmon": {
    "enabled": true,             // 关掉后开始菜单 / 桌面右键的入口消失，接口返回 403
    "top_n": 30,                 // 一次返回多少个进程（按 CPU 或内存排序后取前 N，上限 500）
    "refresh_seconds": 2,        // 前端自动刷新的默认间隔（秒）
    // 服务端两次「真正采集」之间的最小间隔（秒）。多个浏览器同时开着任务
    // 管理器时，靠它可以避免各自触发一次完整的进程枚举。
    "min_interval_seconds": 0.5
  },

  // ★ 虚拟桌面内置的音乐播放器
  //   曲库就是文件系统里的一个目录（不是数据库）：导入 = 把文件复制进去，
  //   所以歌曲在文件管理器里看得见、能备份、能直接用别的播放器打开。
  "music": {
    "enabled": true,                  // 关掉后开始菜单入口消失，接口返回 403
    "library_dir": "music",           // 曲库根目录（相对路径相对本文件解析）
    // true = 每人一个子目录（music/<用户名>），与「每个子用户只看到自己的文件夹」一致；
    // false = 全机共用一个曲库（歌单与播放偏好仍然各人各一份）
    "per_user": true,
    "max_upload_mb": 200,             // 单曲上限，导入与上传都按它算
    "state_path": "music_state.json"  // 歌单与播放偏好（按用户分文件）
  },

  // ★ 桌面歌词：把播放器的「现在在放什么」转发给桌面悬浮窗
  //   （客户端在 desktop-lyrics/，是独立程序；服务端只做内存转发）
  "lyrics": {
    "enabled": true,                  // 关掉后播放器不再上报，悬浮窗会显示明确提示
    // 多久没收到上报就认为「那个源已经不在了」（秒）。
    // 播放时每 0.5 秒报一次、暂停时每 5 秒一次心跳，所以 10 秒足够稳。
    "stale_seconds": 10,
    // 预留的鉴权扩展点：留空 = 不校验（局域网互相信任的默认部署）。
    // 配成任意字符串后，上报与订阅都必须带上同一个 token。
    "token": ""
  },

  "preview": {
    "text_max_kb": 2048       // 文本预览最多读取多少 KB，防止打开超大日志卡死
  },

  "log": {
    "level": "info"           // debug | info | warning | error
  }
}
```

**修改配置后需要重启服务生效**（壁纸例外，界面上改完立即生效）。

### 换端口 / 换根目录

- **换端口**：改 `server.port`，或临时 `python app.py --port 9000`
- **换根目录**：改 `roots[].path`。指向一个不存在的目录时，服务启动会自动创建
- **加目录**：往 `roots` 数组里再加一项即可，桌面上会自动多出对应图标

## 六、修改登录账号密码

### 首选：登录后在界面上改

- **改自己的口令**：开始菜单 →「修改密码」（需要输入当前口令）。
- **给别人改 / 建账号 / 停用**：管理员登录后，开始菜单 →「用户管理」。
  这是多用户下的主要入口：建账号、分配可见目录、停用、强制下线都在那里。

界面上的改动**立即生效**，不需要重启服务。

### 忘记口令 / 进不去界面时：命令行工具

项目提供了专门的工具 `tools/gen_password.py`：

```bat
:: 列出全部账号（谁被停用了、谁有几个可见目录，一眼看清）
python tools\gen_password.py --list

:: 交互式修改口令（推荐，输入时不回显）；默认改现有的第一个管理员
python tools\gen_password.py --set

:: 直接指定口令
python tools\gen_password.py --set --password "MyNewPass123!"

:: 随机生成一个新口令并写入，同时在控制台显示
python tools\gen_password.py --set --random

:: 指定账号（不存在则新建为管理员）
python tools\gen_password.py --set --username stu01 --password "NewPass123!"

:: 只生成一个随机密码和它的哈希（不修改任何文件）
python tools\gen_password.py

:: 只把某个密码转成哈希（用于手工编辑 users.json）
python tools\gen_password.py --hash "MyPass123!"
```

> ★ 口令改的是**用户表 `users.json`**（登录的唯一事实来源），
> 并且会同步写回 `config.json` 的 `auth` 段 —— 后者只在「还没有 `users.json`」
> 时被用来派生第一个管理员，同步一份是为了将来用户表丢了重建时口令不变。
>
> 工具会**递增该账号的 `token_version`**，所以他已登录的浏览器会立即失效 ——
> 这正是「口令泄露后立刻重置」想要的效果。改动立即生效，**不需要重启服务**。
>
> 用户名**不支持改名**：它是任务归属、终端归属与审计日志的键，
> 改名会让这些记录对不上号。要「换个名字」请新建账号，然后把旧账号停用。

**首次启动会自动生成随机口令**，用户名默认 `admin`。口令同时出现在两处：

1. 启动时控制台横幅（醒目打印一次）；
2. 项目根目录的 `FIRST_RUN_PASSWORD.txt`。

> 密码在 `users.json`（以及引导用的 `config.json`）中只以 PBKDF2-HMAC-SHA256
> 哈希形式保存，**没有任何明文**。
> 明文只存在于 `FIRST_RUN_PASSWORD.txt`，登录确认无误后请删除该文件并修改密码。
>
> ⚠️ **本仓库刻意不包含 `config.json` / `users.json` / `FIRST_RUN_PASSWORD.txt` /
> `audit.log.jsonl`**（已在 `.gitignore` 中排除）。
> 它们分别是配置（含 `session_secret`，拿到就能伪造会话 Cookie）、
> 用户表（含每人口令哈希）、明文口令、以及审计日志 ——
> 全部属于**部署数据**，任何情况下都不要提交到仓库。

## 七、注册为 Windows 服务（NSSM 开机自启）

[NSSM](https://nssm.cc/download) 可以把任意程序注册成 Windows 服务，实现**开机自启、
崩溃自动重启、无需登录桌面**。

### 步骤

1. **NSSM 已随项目提供**：`nssm.exe`（v2.24）已经放在本项目目录里，**无需另外下载**。
   - 脚本会先在系统 PATH 中查找 nssm，找不到才使用项目目录内的这一份；
   - 若需要更新版本，可从 https://nssm.cc/download 下载，解压后把 `win64\nssm.exe`
     覆盖到本项目目录（与 `app.py` 同级）即可。

2. **以管理员身份**右键运行 `install_service.bat`。

脚本会自动完成：
- 注册服务 `RemoteFileWeb`
- 设置工作目录为项目目录
- 日志输出到 `logs\service_out.log` / `logs\service_err.log`（超过 10MB 自动轮转）
- 崩溃自动重启（延迟 5 秒）
- 停止时先发 Ctrl+C（让服务有机会清理临时文件），5 秒后再强杀
- 设置开机自动启动并立即启动服务

3. **常用管理命令**：

```bat
sc query RemoteFileWeb        :: 查看状态
net start RemoteFileWeb       :: 启动
net stop  RemoteFileWeb       :: 停止
```

4. **卸载服务**：以管理员身份运行 `uninstall_service.bat`

### 手动注册（参考）

```bat
nssm install RemoteFileWeb "C:\路径\项目\.venv\Scripts\python.exe" "app.py"
nssm set RemoteFileWeb AppDirectory "C:\路径\项目"
nssm set RemoteFileWeb AppStdout "C:\路径\项目\logs\service_out.log"
nssm set RemoteFileWeb AppStderr "C:\路径\项目\logs\service_err.log"
nssm set RemoteFileWeb Start SERVICE_AUTO_START
nssm start RemoteFileWeb
```

> **注意**：服务方式运行时，`soffice` 探测与「回收站删除」都以 SYSTEM 账号身份执行，
> 与你在桌面登录的账号看到的回收站可能不是同一个。若发现回收站删除异常，
> 可把 `delete.use_recycle_bin` 改为 `false` 使用永久删除。

## 八、放行防火墙端口

Windows 防火墙默认会拦截外部访问。**以管理员身份**执行：

```bat
netsh advfirewall firewall add rule name="FileWeb 8000" dir=in action=allow protocol=TCP localport=8000
```

换端口时把 `8000` 改成实际端口。删除规则：

```bat
netsh advfirewall firewall delete rule name="FileWeb 8000"
```

> 首次以交互方式启动时，Windows 也可能弹出「是否允许应用通过防火墙」，
> 勾选**专用网络**并允许即可。

## 九、Office 文档预览（可选安装 LibreOffice）

`doc / docx / xls / xlsx / ppt / pptx` 的预览有两条路线，服务会自动选择：

1. **首选：LibreOffice 无头模式转 PDF**（版式最接近原文）
   - 下载安装：https://www.libreoffice.org/download/download-libreoffice/
   - 安装后**无需重启服务**，在预览窗口点「重新检测 LibreOffice」即可，或重启服务。
   - 也可以在 `config.json` 的 `office.soffice_path` 里写死 `soffice.exe` 的完整路径。

2. **降级：纯 Python 解析 OOXML**（没装 LibreOffice 时）
   - `docx / xlsx / pptx` 本质是 zip + XML，服务会直接解析并生成网页版预览，**文字和表格都能看**，
     但版式与原文有差异（预览页顶部会有黄色提示说明这一点）。
   - 老的二进制格式 `.doc / .xls / .ppt` 无法用这种方式解析，会给出「请安装 LibreOffice」的友好提示，
     不会报错也不会崩溃。

启动横幅会明确显示当前检测结果（下例是已装 LibreOffice 的机器）：

```
  依赖检测：
    LibreOffice : 已找到 -> C:\Program Files\LibreOffice\program\soffice.exe
    缩略图缓存  : D:\Share\thumb_cache
    转换缓存    : D:\Share\office_cache
    删除方式    : 移至回收站
```

未安装时则显示：

```
  依赖检测：
    LibreOffice : 未安装
                  doc/xls/ppt 老格式将无法预览；
                  docx/xlsx/pptx 会用内置解析器降级显示内容。
                  安装地址：https://www.libreoffice.org/download/
```

## 十、安全设计说明

| 风险 | 防护措施 |
|---|---|
| **路径穿越**（`../../Windows`） | 双重校验：① 字符串层直接拒绝任何 `..` 段、绝对路径、UNC 路径；② `realpath` 解析符号链接/目录联接后再做「根目录前缀」比对。注意：开启 `mount_all_drives` 后根目录覆盖整个磁盘，此时绝对路径会先被规范化，落回某个盘内属正常放行；规范化后若跑出所有根目录（例如 UNC 路径）仍会被 403 拒绝 |
| **全盘开放后的误操作** | `protected_paths` 列表中的目录（`C:\Windows`、`C:\Program Files`、`C:\ProgramData` 等）仍然可以**浏览和下载**，但禁止新建/重命名/删除/上传，避免误删系统文件导致 Windows 无法启动。需要完全放开时把该列表清空即可 |
| **明文口令** | 用户表（`users.json`）只存 PBKDF2-HMAC-SHA256 哈希（26 万次迭代 + 随机盐），比较用恒定时间函数 `hmac.compare_digest`；`config.json` 的 `auth` 段同样只存哈希，且仅用于「首次派生管理员」 |
| **未登录访问** | 中间件统一拦截：除 `/api/auth/login`、`/api/auth/status` 外，所有 `/api/*` 未登录一律 **401** |
| **会话安全** | HttpOnly + SameSite=Lax 签名 Cookie，密钥持久化在配置中；前端脚本读不到 Cookie |
| **按用户让会话失效** | 令牌里带该账号的 `token_version`，改口令 / 停用 / 强制下线都会递增它，于是**只**让这个人的旧会话失效（多用户下不能轮换全局 `session_secret`，那会把所有人一起踢下线）。角色与可见目录**实时读用户表**，所以降权、改可见目录下一次请求就生效 |
| **子用户越权访问别人的目录** | 路径解析器**按用户构建**（`AppState.resolver_for`）：子用户只拿到他被分配的那些根，且**不挂载任何磁盘**；「一个根都没有的子用户」拿到的是**空世界**而不是全机（这条与管理员严格区分 —— 弄反就是提权）。未知的根标识直接报错，不再静默退回第一个根 |
| **任务/终端跨用户操作** | 后台任务带归属，取消与查看都要校验归属；命令行名额按人计，**顶替只发生在同一个人的会话之间**（别人满员不会杀掉你的窗口） |
| **管理接口越权** | `/api/users/*` 全部走 `require_admin` 返回 403，且三条护栏挡住「把自己锁在门外」（不能停用自己、不能改自己的角色、不能停用最后一个管理员）。★ 但请记住这是**界面与接口层面**的约束，不是对抗恶意用户的边界（见下） |

> ⚠️ **多用户不是安全边界。** 子用户拥有**全权限命令行**，所以他能绕过以上
> 所有「按用户可见性」的限制：直接读同学的文件、读 `users.json` / `config.json`
> （拿到 `session_secret` 即可伪造管理员会话）、结束别人的进程、`taskkill` 掉本服务。
> 这是与使用场景一起**明确确认并接受**的风险（同机同组学生，机器本来就在他们手上），
> 完整说明见 [MULTIUSER.md](MULTIUSER.md) 第〇节与第九节。
> 这些机制的作用是**防误操作**与**留下审计线索**，不是防有心人。
| **CSRF** | 所有改状态请求（POST/PUT/PATCH/DELETE）必须带 `X-CSRF-Token`（由会话令牌派生），并校验 Origin 同源 |
| **暴力破解** | 同一 IP 连续失败达阈值（默认 5 次）锁定 5 分钟。**客户端 IP 取 TCP 对端地址，默认不采信 `X-Forwarded-For`** —— 该头可被随意伪造，早先无条件采信它时，换一个伪造值就能让失败计数归零、完全绕过锁定（实测已复现）；uvicorn 的 `proxy_headers` 也按 `auth.trusted_proxies` 联动，避免它在中间件之前就把来源地址改写掉。只有显式配置了可信代理才会采信该头 |
| **存储型 XSS** | 上传的 `.html/.svg/.xml` 等**内联输出时强制降级为 `text/plain`**；所有响应带 `X-Content-Type-Options: nosniff`；HTML 页面带严格 CSP（`script-src 'self'`） |
| **上传可执行文件** | 按扩展名黑名单拦截 `.exe/.bat/.ps1/.msi/...`，且会同时检查完整后缀链（`evil.bat.exe` 也拦得住） |
| **文件名攻击** | 清洗非法字符、拦截 Windows 保留设备名（`CON/NUL/COM1`…）、去除尾部点与空格、只取最后一段防止夹带路径 |
| **解压炸弹 / 超大文件** | 缩略图**在解码前**做显式像素预检（上限 8000 万像素），并对 JPEG 先用 `draft()` 按 1/2、1/4、1/8 降采样再解码；文本预览限制读取体积；Office 解析限制单个 XML 部件大小（64MB）与表格行列数 |
| **误删磁盘根目录** | 拒绝把「根目录本身」作为删除/打包/重命名的目标。开启 `mount_all_drives` 后每个盘符都是一个可访问根目录，而根目录既不在 `protected_paths` 里也不是只读，此前 `paths: [""]` 这类请求可以通过全部校验 |
| **命令行窗口（高危）** | 默认开启，但 WebSocket 与普通接口走**同一套认证**，并额外校验 `Origin` 同源；会话 ID 随机且与当前会话令牌绑定，无法枚举或跨会话复用。它**等价于把服务器 shell 交给任何能登录本服务的人**（服务方式下是 SYSTEM 权限），不需要时请关闭 `terminal.enabled` |
| **缓存无限增长** | 缩略图与 Office 转换缓存都有体积上限（`thumbs.max_cache_mb` / `office.max_cache_mb`），超出后按最旧优先清理；转换超时会**连同子进程一起结束**，遗留的 `office-*` 临时目录按年龄回收 |
| **接口暴露** | 自动文档（`/docs`、`/openapi.json`）已关闭 |
| **分离会话的寿命变长** | 「断开不再结束会话」意味着一个 shell 可能比一次登录活得更久，所以会话与「创建它时的登录令牌摘要」强绑定：连 WebSocket 必须提供**同一个**令牌才能接管，即使 sid 因某种原因泄露也**无法被他人接管**（否则 sid 跨身份可用就等于把别人的 shell 变成公共资源）。未知 sid 在**握手阶段**就被拒，不给探测有效 sid 的机会 |
| **解压写入任意文件（Zip Slip）** | 压缩包内的条目名是**外部可控**的，所以解压没有使用 `extractall`，而是逐条目校验：拒绝绝对路径、盘符（`C:`）、UNC、任何 `..` 段，再用 `realpath` 二次确认没跑出目标目录；符号链接/硬链接/设备文件条目一律**跳过**（否则等于给出一个「写任意链接」的跳板）。7z/RAR 先解到目标目录下的暂存目录，再按校验过的名字搬过去 |
| **解压炸弹** | 限制条目数、解压后总体积与单文件体积（`archive` 段），超限直接报错中止而不是截断；体积在**落盘之前**就要先算一遍，避免解压到一半才发现空间不够 |
| **解压覆盖已有文件** | 目标存在同名顶层项时**整体拒绝**（`409`）并列出冲突名称，不做覆盖、不做半途而废 |

### 部署建议

- 本服务默认使用 **HTTP**，局域网内**密码是明文传输**的。若对安全性要求高：
  - 只在内网/可信局域网使用；或
  - 在前面加一层 Nginx/Caddy 做 HTTPS（自签证书即可）
- 不要把端口直接映射到公网
- 根目录建议使用专用目录（默认 `D:\Share`），不要直接共享整个系统盘
- 定期修改密码；不再需要时删除 `FIRST_RUN_PASSWORD.txt`

> 照片库动辄几十上百 GB，复制一份在时间与空间上都不可接受。
>
> ★ 索引里**只存根标识 + 相对路径，绝不存绝对路径**，每次读取都要重新过一遍
> 当前用户的路径解析器 —— 所以「手工把 `photo_index.json` 里的 relpath 改成
> `../../`」读不出根目录外的文件。存绝对路径的话，编辑一个 JSON 就等于任意文件读取。
>

> `photo_index.json` 是**派生缓存**（指纹/EXIF/尺寸）。重建索引永远不动用户数据 ——
> 合成一张表的话，一次扫描失败就可能冲掉用户改了半天的几百个时间戳。
>
> ★ 每张照片的**内容指纹**（前 256KB + 大小）是编辑记录的挂靠点，所以文件被移动或
> 改名之后，重扫能把编辑认回来。`photos.enabled=false` 时全部接口返回 **403**，
> 前端也不显示入口（同一个判断）。
>
> ⚠️ **编辑只写这两个 JSON，原图一个字节都不改**（写回 EXIF 要重编码 JPEG，
> 画质会掉、还会丢厂商信息）。`.heic/.heif` 没有解码器，导入时会明确跳过并说明原因。

| POST | `/now-playing` | 播放器上报「现在在放什么」。三种 `type`：`song`（整首，含歌词）/ `progress`（进度，每 0.5 秒）/ `stop`（停止） |
| GET | `/now-playing` | 当前状态（`?user=` 只看某人，`?sources=1` 附带「谁在放」的清单，供排障与托盘菜单用） |
| WS | `/ws/lyrics` | 悬浮窗订阅（`?user=` 可选）。连上立刻收到一条当前状态；空闲时也会收到 `idle` 的一条 |

> ★ 这三个路径**故意不在 `/api` 下**：桌面歌词悬浮窗是仓库里 `desktop-lyrics/`
> 那个独立客户端，它**没有登录会话的 Cookie**，而且必须在没有人打开浏览器的深夜
> 也能连上。按局域网内互相信任的部署前提，这里不做登录校验（中间件只对 `/api`
> 生效）—— 代价是局域网内任何人都能推文字过来、也能看到别人在放什么歌。
> 想收紧的话给 `lyrics.token` 配一个值即可（见配置详解），客户端在「连接设置」里
> 填同一个值，其余代码一行都不用改。
>
> 服务端**不信任**上报内容：类型、长度、数值全部在 `fileweb/lyrics.py` 里做截断与
> 归一（歌词最多 2000 行、单行 500 字、请求体上限 2MB），所以局域网里有人乱发也
> 撑不爆内存。状态只在内存里，**进程重启即忘**（这本来就是实时状态，不是数据），
> 播放器下一次进度上报会带着 `needSong` 自动把它补齐。

### 压缩包浏览 / 文件搜索 / 后台任务
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/fs/archive` | 列出压缩包内的条目（**只读、不解压**）。`root` / `path` / `limit`（默认回传前 500 条）。返回条目表、条目数、展开后总体积，以及**与目标目录的同名冲突** |
| GET | `/api/fs/search` | 按**文件名**递归搜索（不搜内容）。`q`（至少 2 个字符）/ `root`（留空 = 所有可访问根）/ `limit` |
| POST | `/api/auth/password` | 修改登录口令。需 `current_password` + `new_password`（≥ 8 位）。**校验当前口令**，成功后**轮换会话密钥** |
| GET | `/api/jobs` | 后台任务列表（最近的在前）+ 并发统计 |
| GET | `/api/jobs/{id}` | 单个任务的进度与结果（终态任务的 `result` 与同步接口形状一致） |
| POST | `/api/jobs/{id}/cancel` | 请求取消（**协作式**：只打标记，任务在下一个检查点停止） |

> **压缩包浏览**复用了解压流程的第一道安全闸门 `archive.list_entries`，
> 所以列表里看到的名字与真正解压时落盘的名字**完全一致**，不会「看到 A、解出 B」。
> 加密包、损坏包都会给出可读的中文原因，而不是 500。
>
> **搜索有三重刹车**（结果数 / 扫描条目数 / 时间预算），任一触发都会
> **带着已有结果返回**并把 `truncated` 置真、在 `reason` 里说明原因 ——
> 开了 `mount_all_drives` 之后这就是「全盘搜索」，不设限会把服务占住好几分钟。
>
> `POST /api/fs/copy`、`/api/fs/move`、`/api/fs/extract` 新增可选字段
> **`background: true`**：置真时立刻返回 `job_id`，实际操作在后台队列里跑，
> 前端据此显示进度并可取消。**默认仍是同步**（请求挂到做完为止），
> 以免破坏既有调用方 —— 命令行与脚本可以继续用同步那一档。
> 校验（只读根目录、路径穿越、重名冲突）仍然在提交那一刻同步完成，
> 不会把 4xx 降级成「任务失败」。

### 内容与预览
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/fs/raw` | 输出文件原始内容（**支持 Range**；`download=1` 作为附件下载） |
| GET | `/api/fs/thumb` | 图片缩略图（JPEG，100×100，服务端缓存） |

| POST | `/api/fs/text` | **保存文本**（全文 + 编码/BOM/换行符 + 并发凭据；详见下） |
| GET | `/api/fs/office` | Office 预览（返回 `pdf` / `html` / `unsupported` 三种模式） |
| GET | `/api/fs/office/pdf` | 输出转换后的 PDF（供 pdf.js 使用） |

> `POST /api/fs/text` 的请求体是**全文**，不是补丁：
> `{root, path, text, encoding, bom, newline, base_mtime, base_size}`。
> `text` 必须是 **LF 归一化**的，服务端按 `encoding` / `bom` / `newline` 还原原始字节形态。
> `base_mtime` / `base_size` 是打开时从 `GET` 拿到的那两个值（并发凭据）：
> 磁盘现状与之不符时返回 **`409` 且不写任何内容**，客户端必须重新载入而不是重试。
> 其余失败码：`400` 非文本/编码不支持/文件过大不宜在线编辑、`403` 只读根目录、
> `404` 文件已不存在、`413` 提交内容超出上限。

> 上传接口刻意没有使用 `multipart/form-data`：Starlette 解析 multipart 时会先把整个文件
> 落到系统临时目录再让我们拷贝一次，上传 2GB 要多占 2GB 的 C 盘空间和多一倍磁盘 IO。
> 改成原始请求体后可以边收边写目标文件，零额外空间占用。

## 十二、常见问题 FAQ

**Q1：局域网其他电脑打不开？**
1. 确认服务监听 `0.0.0.0`（`config.json` 的 `server.host`）
2. 放行防火墙端口（见[第八节](#八放行防火墙端口)）
3. 确认用的是服务器**局域网 IP**，不是 `127.0.0.1`
4. 在服务器本机先试 `http://127.0.0.1:8000`，能开说明服务正常，问题在网络/防火墙

**Q2：端口被占用启动失败？**
换端口：`python app.py --port 9000`，并同步放行新端口的防火墙。
查看占用：`netstat -ano | findstr :8000`

**Q3：视频拖动进度条没反应？**
后端已实现 HTTP Range（返回 206）。若仍不能拖动，通常是**该视频编码浏览器不支持**
（如 MKV 容器、H.265）；可以下载后用本地播放器打开。

**Q4：doc/xls/ppt 提示无法预览？**
本机没装 LibreOffice。老格式只有 LibreOffice 能转换，装上即可（见[第九节](#九office-文档预览可选安装-libreoffice)）。
`docx/xlsx/pptx` 不受影响，会走内置解析器降级预览。

**Q5：删除报错 / 没进回收站？**
目标盘不支持回收站（网络驱动器、非 NTFS 分区），或服务以 SYSTEM 身份运行时回收站不可用。
把 `config.json` 里 `delete.use_recycle_bin` 改成 `false` 使用永久删除。

**Q6：中文文件名乱码？**
服务全程使用 UTF-8 并做 URL 编码，中文名下载时用 RFC 5987 的 `filename*` 传递。
若仍有问题，请确认不是第三方代理/下载工具改写了响应头。

**Q7：上传大文件失败？**
1. 确认不超过 `upload.max_file_size_mb`
2. 确认目标磁盘剩余空间充足（服务会在开始前用 `Content-Length` 预检）
3. 若前面套了 Nginx，需要放开 `client_max_body_size`

**Q8：如何完全离线部署？**
`static/vendor/` 已经内置了 winbox.js、pdf.js、xterm.js 与 CodeMirror（含各语言 mode），
把整个项目目录拷到目标机器，
用 `pip download -r requirements.txt -d wheels` 在有网机器下载依赖后离线 `pip install` 即可。

**Q9：登录页一直显示锁屏？**
这是刻意的 Windows 行为：先显示大时钟，点击任意位置或按任意键才出现密码框。
在地址栏 URL 后加 `#login` 可直达密码输入框（方便收藏）。

**Q10：忘记密码了？**
```
python tools\gen_password.py --set --random
```
然后重启服务。

**Q10b：在命令行里敲 `python` 会不会卡住？**

不会。早先终端用的是**管道**而不是真终端，裸 `python` 检测到 stdin 不是终端，
会改成「把 stdin 当脚本读」，于是你后面敲的每一行都被它吞掉、提示符再也不回来，
看起来就像卡死。现在后端用 **ConPTY（pywinpty）** 提供了真正的 TTY，
裸 `python` 会正常进入交互式解释器。

如果某台机器上没装 `pywinpty`（会自动退回管道模式），那就别用裸 `python`，
改用 `python -c "..."` 或 `python 脚本.py` —— 这两个不读 stdin，不会卡。

真卡住了怎么办：按 `Ctrl+C`（原生中断）；或用工具栏的**「中断」**按钮，
它会杀掉卡住的子进程但保留 shell（当前目录还在）。

**Q11：命令提示符窗口能关掉吗？**

能。把 `config.json` 里的 `terminal.enabled` 改成 `false` 再重启服务，
开始菜单与桌面右键里的入口就会消失，`POST /api/terminal/session` 也会返回 403。

**Q12：复制/移动几十 GB 时界面像卡住了？**

以前是预期行为（同步执行）。**现在不会了**：复制 / 移动 / 解压都走后台任务，
右下角会出现进度面板，显示进度条、已处理条目与体积、当前文件名，并可以随时取消；
期间界面照常可用，甚至可以同时跑多个任务。

注意两点：
1. **关掉浏览器不会取消任务** —— 任务活在服务进程里，继续跑完；重新打开页面时
   面板会把它们重新列出来。要停就点面板上的取消。
2. **取消是协作式的**，点下去会显示「正在取消…」，任务在下一个检查点（一次分块
   写完之后）才真正停下。

「打包下载」和「压缩」仍是同步的，选到数十 GB 时请求依然会等较久。

**Q13：前面挂了 Nginx，登录失败锁定好像不太对？**

需要在 `config.json` 的 `auth.trusted_proxies` 里填上代理所在机器的 IP
（例如 `["127.0.0.1"]` 或 `["10.0.0.0/8"]`）。默认是空数组，含义是
**完全不采信 `X-Forwarded-For`**：这时如果所有请求都来自代理，
锁定就会按代理那一个 IP 计数，可能把所有人一起锁掉。
反过来说，没有可信代理时千万**不要**随便填这个字段 ——
`X-Forwarded-For` 是客户端可以随意伪造的，早先无条件采信它时，
攻击者换个伪造值就能让失败计数归零、完全绕过锁定。

## 十三、已知限制

- **未实现**：批量重命名、**回收站查看与还原**（删除虽会进系统回收站，但 Web 界面里看不到已删除项，需到 Windows 回收站手动还原）、HTTPS（建议由反向代理承担）
  - （「在线解压」此前列在这里，现在已经实现了，见「压缩与解压」一节）
  - （「文件搜索」此前列在这里，现在已经实现了 —— 开始菜单搜索框，见「文件搜索」一节）
  - （「多用户 / 权限分级 / 操作审计日志」此前列在这里，现在都已经实现了 ——
    见「多用户（管理员 / 学生）」一节与 [MULTIUSER.md](MULTIUSER.md)。
    ★ 但请务必读那里的风险说明：**「子用户只能看到自己的文件夹」是界面便利，
    不是安全边界**）
- **复制 / 移动 / 解压已改为后台任务**：右下角有进度面板、可取消，不再把界面锁住。
  但**压缩**与**打包下载**仍然是同步的，选到数十 GB 时请求依旧会等较久
- 后台任务**不跨服务重启**：重启后队列清空、进行中的任务中止（不做断点续传，
  也不假装能做）。任务结束后的记录保留 10 分钟供查询
- **拖动不能拖到真实桌面**：只能在 Web 虚拟桌面内部拖动（浏览器安全限制，无法绕过）
- **桌面歌词盖不住「独占全屏」的游戏**：这是 Windows 合成器的限制（Discord / Steam /
  NVIDIA 的浮层同样盖不住），不是本项目的毛病。把游戏改成**无边框窗口化**即可正常显示。
  另外悬浮窗是 Electron 程序（每台机器约 150~200MB 内存），因为它要用 HTML/CSS 画
  描边字与平滑滚动；如果你更在意体积，可以照 `desktop-lyrics/` 的结构换成原生窗口，
  服务端的转发协议不用改
- 命令行窗口现在是**真正的终端**（ConPTY + xterm.js）：裸 `python`、Tab 补全、`Ctrl+C` 中断、中文输入法都可用。若目标机器没装 `pywinpty`，会自动退回管道模式，届时这些交互能力都会缺失（窗口内会明确提示）
- 全屏类程序（如 `vim`）在 ConPTY 下通常可用，但**没有逐一验证**；`shell` 配成 PowerShell 的分支也未实测
- **`root` 目录既不能删除也不能整个打包**（`paths: [""]` 会被 403 拒绝），这是有意为之
- Office 降级预览只提取文字与表格，**不还原版式、图片和图表**；`.doc/.xls/.ppt` 老格式必须装 LibreOffice
- 拖拽上传依赖浏览器能力，**不支持拖拽整个文件夹**（会忽略目录）
- **任务管理器的 GPU 利用率只支持 NVIDIA 显卡**：走 `nvidia-smi` 命令行读取；
  Intel / AMD 显卡需要 Windows PDH 性能计数器，尚未实现，此时卡片会明确显示
  「不可用」并说明原因（而不是显示一个会让人误判的 0%）。另外服务端启动后的
  **第一轮**进程 CPU 必然全是 0（psutil 要先建立基线才能算差值），第二轮起才准确
- 任务管理器是**只读**的，没有「结束进程」；需要动进程请用命令行窗口
- 缩略图仅支持浏览器/Pillow 能解码的图片格式（不含 SVG、HEIC 视 Pillow 支持情况）
- 打包下载为同步生成，选中体积非常大时（数十 GB）请求会等待较久

关于**压缩与解压**：
- **不支持加密（带密码）压缩包**：会明确提示「需要密码才能解压」，但确实解不开；创建时也不能设密码
- **RAR 依赖 WinRAR**：没装 WinRAR 时创建/解压 RAR 会返回 501 并说明原因，其余格式不受影响（7z 走纯 Python 的 `py7zr`，不需要外部程序）
- 压缩与解压：**解压已改为后台任务**（有进度、可取消）；**压缩仍是同步**的，
  打大包会让请求等待较久（与「打包下载」同一个问题）
- 打包时**不跟进符号链接与目录联接**，被跳过的项会在结果里列出；解压时压缩包内的链接条目同样被跳过
- 解压**不会覆盖**已有同名项（整体拒绝并列出冲突名），这是刻意的

关于**会话持久**：
- 分离的会话**仍然占用**名额（它确实还占着一个 shell）。名额是按**人**算的
  （`terminal.max_sessions`，默认 5；另有 `terminal.max_sessions_total` 全机兜底）。
  自己的名额满了时，一个「没有客户端连着且已闲置 `evict_grace_seconds`」的旧会话
  会被自己的新会话顶掉，所以不会把自己锁死。
  ★ **顶替只发生在同一个人的会话之间** —— 别人开窗口绝不会杀掉你的窗口。
  另外 `idle_timeout_seconds` 默认是 `0`（不自动回收），所以长期挂着的窗口
  会持续占用系统资源，必要时请手动关闭
- 分离期间输出超过 `terminal.max_output_kb` 的部分会被丢弃（重连时前端会提示「有输出被截断」）
- 窗口布局恢复是**尽力而为**：目录已被删除、盘符未挂载、状态文件损坏等情况会退化为「跳过该窗口」或「用默认布局」，不会因此打不开桌面
- 界面状态与快捷方式**按用户分开存**，所以多人共用时不会互相覆盖布局（见下文「关于多用户」）

关于**多用户**（动手前请先读 [MULTIUSER.md](MULTIUSER.md)）：
- ⚠️ **「子用户只能看到自己的文件夹」是界面与接口层面的便利，不是安全边界。**
  子用户拥有**全权限命令行**，因此他可以：用 cmd 直接读同学的文件、
  读 `users.json` 与 `config.json`、伪造管理员会话 Cookie、结束别人的进程，
  甚至可以 `taskkill` 掉本服务。这些是**明确确认并接受**的风险
  （使用场景是同机同组学生、机器本来就在他们手上）
- 服务通常以 SYSTEM（或等价高权限）运行：命令行里的误操作（`del /s`）可以直接毁掉系统，
  应用层的 `protected_paths` **拦不住终端**
- 若需要真正的隔离，必须给每个用户单独开 Windows 账号并以低权限身份运行服务、
  用 ACL 划分目录 —— 那是另一个量级的工程，不在本项目的范围内
- **审计日志只记录账号层面的动作**（登录/登出/改密/账号增删改），
  不记录文件浏览与上传下载；也就是说「谁下载了哪个文件」是查不到的
- 「在线」是**内存表**（最近 5 分钟有活动），服务重启即清空；
  持久记录请看审计日志。会话是无状态签名 Cookie，服务端**无法枚举**有效会话，
  所以这里记的是「我最近见过谁」而不是精确的会话清单
- 管理界面的「活跃会话数」指的是**命令行窗口数**，不是登录次数

关于**文本编辑**：
- **混合换行的文件会被统一**：编辑器只记录并沿用「文件中**第一个**换行符的风格」（确定、可复现），
  所以一个既有 CRLF 又有 LF 的文件保存后，会全部变成首行那种风格。不是数据丢失，但 diff 会变大，
  对 `.bat` 这类对 CRLF 敏感的文件尤其明显
- **过大的文件不能就地编辑**：预览只读取开头 `preview.text_max_kb`（默认 2MB）那一段，
  为避免「保存时把后面的内容整段删掉」，超出这个大小的文件会**明确拒绝编辑**，
  请走「下载 → 本地编辑 → 上传」
- **不会覆盖别人的修改**：保存时会带上你打开那一刻的文件时间与大小，若磁盘上已被改动，
  保存会被**拒绝并提示重新载入**，而不是静默覆盖
- 编辑器窗口纳入会话持久化，但**只记录路径与位置，不还原未保存的内容** ——
  重新打开页面时是重新从磁盘载入，未保存的编辑会丢失（这是刻意的：把旧缓冲写回磁盘更危险）
- 支持语法高亮的扩展名有限；未覆盖到的扩展名以纯文本打开（功能仍可用，只是没有高亮）

关于**音乐播放器**：
- 只支持浏览器能解码的格式（mp3 / flac / m4a / aac / ogg / opus / wav / webm）。
  **wma / ape / midi / aiff 无法播放**，导入时会被明确拒绝 —— 这是浏览器能力决定的，不是没做
- **不解析音频内嵌的专辑封面与内嵌歌词**：封面用歌名散列出的渐变占位图，
  歌词只认歌曲旁边的同名 `.lrc`（或手动上传/粘贴）。要看内嵌封面/歌词请用本机播放器
- 时长由**浏览器**读元数据得到，服务端不解析音频，所以列表里的时长可能短暂显示 `--:--`
  （只在当前视图的前 40 首里逐个探测，串行进行）
- 上传超过单曲上限时，服务端按 `Content-Length` **提前拒绝**，此时浏览器可能只看到
  「连接被中断」而不是 413（前端会先按文件大小自查，正常操作看不到这条）
- 曲库是**扁平的**（不建子目录）：导入时按文件名铺开，同名自动改名。想分类请用**歌单**
- 播放器是**单例窗口**：再点一次入口只会把已有窗口拉到前面，不会开第二个（两个一起响没有意义）。
  位置与大小会被持久化；**窗口内的播放进度不还原**（`music.enabled` 后来被关掉时，
  存档里的这个窗口也不会再被还原出来）
- 恢复上次那首歌时**不会自动播放**（浏览器也会拦掉没有交互的自动播放），
  需要手动点一下播放键

## 开发与测试

```bat
:: 前端资源缺失时重新下载（构建期用一次，不影响离线部署）
python tools\fetch_vendor.py

:: 启动（开发模式，改后端代码自动重载）
python app.py --reload --log-level debug

:: 跑回归测试（只用标准库，不需要额外安装 pytest / httpx）
.venv\Scripts\python.exe -m unittest discover -s tests -t . -v
```

前端为纯原生 ES Module，浏览器直接加载，**无需任何构建步骤**。
后端共 12 个路由模块（认证 / 用户管理 / 系统 / 文件 / 内容 / 虚拟桌面 / 命令行 /
系统监控 / 后台任务 / 音乐播放器 / 照片 / 桌面歌词），可按需扩展。

测试覆盖的都是「曾经真实出过问题」的点：路径穿越防护（含能骗过字符串层检查的
`....//` 写法）、`X-Forwarded-For` 伪造绕过登录锁定、根目录误删、缩略图的像素上限
与缓存上限、Office 转换抛异常时必须仍能降级预览、**子用户越权访问别人的根**、
**终端名额顶替不跨用户**、**任务归属隔离**、**播放器不能成为绕过文件可见性的旁路**、
**关掉浏览器后歌词会不会赖在屏幕上**、**照片被移动后改过的时间还跟不跟着走**、
**重建索引会不会冲掉用户的编辑**、以及**「测试写脏真实部署」**（见下）等。
改动这些地方前请先跑一遍。

### 前端逻辑的用例（`tests/js/`）

前端不是「不用测」的：歌词上报、悬浮窗重连、歌词与时间的对应，这三块**出错都不
吭声**（上报失败是故意静默的，悬浮窗连不上就是一片空白），所以只能靠用例把行为
钉住。它们**不需要浏览器也不需要 Electron**，用 node 直接跑：

```bat
node tests\js\nowplaying.test.mjs                 :: 上报：节流/合并待发/needSong/退避
node tests\js\desktop-lyrics-client.test.mjs      :: 连接：真起一个 WS 服务端测重连与轮询兜底
node tests\js\desktop-lyrics-overlay.test.mjs     :: 渲染：时间外推、暂停冻结、不重复写 DOM
```

上面这些会被 `unittest discover` 通过 `tests/test_js_units.py` 一并跑到
（没装 node 时自动跳过，不会让整套测试变红）。★ 它们跑的是**与线上同一份 JS**，
不是在 Python 里重写一遍逻辑 —— 重写一遍只能验证「我以为的逻辑」，两边还会各自演化。

> 测试会自己起一个 `python app.py` 子进程（随机端口 + 临时配置），只暴露一个临时
> 目录，不会碰到真实磁盘，跑完自动清理。之所以要用真实入口而不是在进程内构造
> `uvicorn.Config`，是因为 `proxy_headers` 这类参数的默认值本身就是被测试对象。
>
> ★ **所有「默认落在项目根目录」的目录与文件都由脚手架重定向到临时目录**，
> 并且有一条结构性守卫盯着它：`DEFAULT_CONFIG` 里凡是**默认值非空的路径类配置项**
> （键名以 `_path` / `_dir` 结尾，或名为 `path`）都必须登记在
> `tests/_harness.py` 的 `STATE_PATH_TARGETS` 中，否则测试直接失败。
> 这个坑在本项目已经踩过四次（`config.json` 被覆盖导致服务换端口失联、
> 真实 `user_state.json` 里混进测试窗口、真实 `desktop_shortcuts.json` /
> `audit.log.jsonl` 被写入），所以做成了机制。
